## Git의 원리와 충돌

> Git은 파일 상태를 스냅샷으로 기록하는 분산 버전 관리 시스템입니다. 파일 내용은 blob, 디렉터리 구조는 tree로 표현하고, commit은 루트 tree와 부모 커밋 등을 참조합니다. 브랜치는 커밋을 가리키는 참조이고 HEAD는 보통 현재 브랜치를 가리킵니다. 작업 트리의 변경을 add로 인덱스에 준비하고 commit으로 로컬 이력에 기록한 다음 push로 공유합니다.
>
> 이력이 갈라진 두 브랜치를 병합할 때는 일반적으로 공통 조상과 양쪽 상태를 비교하는 3-way merge를 합니다. 같은 부분을 서로 다르게 수정하거나 한쪽에서 삭제한 파일을 다른 쪽에서 수정하면 Git이 결과를 자동으로 결정하지 못해 충돌할 수 있습니다. 해결할 때는 양쪽 의도를 확인해 파일을 정리하고 검증한 뒤 add와 commit 또는 rebase --continue로 완료합니다. push의 non-fast-forward 거절은 원격 이력을 덮어쓰지 않기 위한 검사이므로 내용 충돌과는 구분합니다.

## 버전 관리 시스템의 유형

- **Local**: 로컬 컴퓨터에서 버전을 관리한다.
- **Centralized**: 중앙 서버를 중심으로 관리한다. 서버 장애 시 서버에 접근하는 커밋·공유 등의 작업은 제한되지만 로컬 파일 편집까지 불가능해지는 것은 아니다.
- **Distributed**: 일반적인 전체 clone은 로컬에 이력과 객체를 복제하므로 오프라인에서도 커밋·로그 조회·브랜치 작업이 가능하다. 다만 shallow/partial clone은 이력이나 객체 일부를 생략할 수 있으며, 분산 구조가 충돌 자체를 없애 주지는 않는다.

## 작업 트리, 인덱스, 저장소

```text
작업 트리(실제 파일) --git add--> 인덱스(다음 커밋의 준비 상태)
인덱스 --git commit--> 로컬 저장소 --git push--> 원격 저장소
```

- **Modified**: 추적 파일의 작업 트리 내용이 인덱스와 다르다.
- **Staged**: 인덱스의 내용이 HEAD 커밋과 달라 다음 커밋에 반영될 예정이다.
- **Committed**: 내용이 커밋에 기록되어 있다.
- **Untracked**: 아직 Git이 추적하지 않는 파일이다.

`git add`는 실행 당시 내용을 인덱스에 반영한다. 이후 같은 파일을 다시 수정하면 staged 변경과 unstaged 변경이 동시에 존재할 수 있다. `git commit`은 기본적으로 인덱스를 기록한다.

## 주요 Git 명령어

아래 `<파일>`, `<브랜치>` 등은 실제 값으로 바꿔 입력한다.

| 기능 | 명령어 | 정확한 동작 |
| :--- | :--- | :--- |
| 초기화 | `git init` | 로컬 Git 저장소 생성 |
| 이력 조회 | `git log` | 커밋 이력 조회. 셸 명령어 실행 기록이 아님 |
| 그래프 조회 | `git log --oneline --graph --decorate --all` | 브랜치와 커밋 관계 확인 |
| 상태 조회 | `git status` | 추적·스테이징·작업 트리 상태 확인 |
| 수정 비교 | `git diff` | 작업 트리와 인덱스 비교 |
| 스테이징 비교 | `git diff --staged` | 인덱스와 HEAD 비교 |
| 브랜치 조회 | `git branch` | 로컬 브랜치 목록. `-a`는 원격 추적 브랜치도 표시 |
| 브랜치 생성 | `git branch <브랜치>` | 생성만 수행하며 이동하지 않음 |
| 브랜치 이동 | `git switch <브랜치>` | 기존 브랜치로 이동 |
| 생성 후 이동 | `git switch -c <새브랜치>` | 새로 생성하고 이동. 이미 있는 이름이면 실패 |
| 브랜치 삭제 | `git branch -d <브랜치>` | 병합 여부를 검사하여 삭제. `-D`는 검사 없이 강제 삭제 |
| 브랜치 이름 변경 | `git branch -m <새이름>` | 현재 브랜치 이름 변경 |
| 스테이징 | `git add <파일>` | 해당 파일의 현재 변경을 인덱스에 반영 |
| 현재 경로 스테이징 | `git add .` | 현재 디렉터리와 하위 경로의 추가·수정·삭제 반영. 무시된 미추적 파일은 제외 |
| 전체 스테이징 | `git add -A` | 저장소 전체의 추가·수정·삭제 반영. 무시된 미추적 파일은 제외 |
| 커밋 | `git commit -m "메시지"` | 인덱스 상태를 로컬 커밋으로 기록 |
| 원격 조회 | `git remote -v` | 원격 이름과 주소 확인 |
| 가져오기 | `git fetch origin` | 원격 객체를 받고 원격 추적 참조 갱신. 현재 브랜치에 자동 통합하지 않음 |
| 가져와 통합 | `git pull --no-rebase origin main` | 원격 main을 가져와 **현재 브랜치에** merge 방식으로 통합 |
| 직선 전진만 허용 | `git pull --ff-only origin main` | fast-forward 가능한 경우에만 통합하고 이력이 갈라졌으면 실패 |
| 푸시 | `git push origin main` | 로컬 main의 커밋을 전송하고 원격 main 갱신 요청. 미커밋 파일은 전송하지 않음 |
| 파일 삭제 | `git rm <파일>` | 작업 트리와 인덱스에서 삭제. 원격 반영에는 commit과 push 필요 |
| 추적 해제 | `git rm --cached <파일>` | 작업 트리 파일은 남기고 인덱스에서 제거. 다음 커밋에 삭제가 기록됨 |
| 파일 이름 변경 | `git mv <기존> <새이름>` | 파일 이동 및 인덱스 반영. Git은 비교 시 유사도를 통해 rename을 탐지 |
| 무시 설정 | `.gitignore` | 의도적으로 추적하지 않을 파일 지정. 이미 추적하는 파일에는 소급 적용되지 않음 |

`origin`은 관례적인 원격 이름이다. `origin/main`은 서버 브랜치 자체가 아니라 **로컬에 기록한 원격 main의 상태**이므로 fetch 전에는 오래된 정보일 수 있다. `pull`의 통합 방식은 옵션과 설정에 따라 달라지므로 예제에서는 의도를 명시한다.

## 되돌리기: restore, reset, revert 구분

아래 예제는 HEAD 커밋이 존재하고, `HEAD~1` 예제는 부모 커밋도 있는 상황을 전제로 한다.

| 목적 | 명령어 | 영향 |
| :--- | :--- | :--- |
| 스테이징 취소 | `git restore --staged <파일>` | HEAD 기준으로 인덱스만 복원. 작업 트리와 커밋 이력은 유지 |
| 기존 방식의 스테이징 취소 | `git reset HEAD -- <파일>` | 위와 같은 목적. 브랜치 포인터나 커밋 이력은 바꾸지 않음 |
| 미스테이징 수정 폐기 | `git restore <파일>` | 기본적으로 인덱스 기준으로 작업 트리 복원. staged 변경과 커밋은 유지 |
| 파일의 미커밋 변경 전체 폐기 | `git restore --source=HEAD --staged --worktree <파일>` | 해당 파일의 인덱스와 작업 트리를 HEAD로 복원. 커밋 이력은 유지 |
| 현재 커밋 상태로 복원 | `git reset --hard HEAD` | 인덱스와 작업 트리의 추적 파일 변경 폐기. `git reset hard`는 잘못된 표기 |
| 마지막 커밋에서 브랜치 되돌리기 | `git reset --soft HEAD~1` | 브랜치 포인터만 부모로 이동. 인덱스와 작업 트리 유지 |
| 커밋과 스테이징 되돌리기 | `git reset --mixed HEAD~1` | 브랜치와 인덱스를 부모로 되돌리고 작업 트리 유지 |
| 부모 커밋 상태로 복원 | `git reset --hard HEAD~1` | 브랜치·인덱스·작업 트리를 부모 상태로 되돌림 |
| 커밋 효과 취소 | `git revert HEAD` | HEAD의 변경을 반대로 적용하는 새 로컬 커밋 생성. 원격 반영에는 push 필요 |

`restore`와 `reset --hard`는 미커밋 변경을 잃게 할 수 있다. `--hard`는 모든 미추적 파일을 청소하는 명령은 아니지만, 추적 파일 복원을 방해하는 미추적 파일·디렉터리를 삭제할 수 있다. 공유한 커밋을 취소할 때는 이력을 재작성하는 reset보다 revert를 우선 고려한다. merge 커밋의 revert에는 `-m`으로 기준 부모를 지정해야 한다.

`git reflog`로 로컬 참조 이동 기록을 찾아 이전 커밋을 복구할 수 있지만, 기록 만료와 객체 정리가 있으므로 영구 백업은 아니다. 커밋하지 않은 수정의 복구도 보장하지 않는다.
